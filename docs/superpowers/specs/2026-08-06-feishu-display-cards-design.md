# 飞书实时显示卡片设计

## 目标

将 Hermes v0.20.0 在飞书中的一轮对话恢复为清晰的三段式显示：实时状态卡、实时执行过程卡、最终回复卡。图片只作为版式参考，所有内容必须来自当前运行状态，不能套固定模板。

## 用户可见结果

一轮对话按以下顺序显示：

1. 用户消息。
2. 状态卡：先显示“已收到，正在思考…”，随后实时更新当前阶段、实际模型、实际服务商和实际上下文占用。
3. 执行过程卡：首次工具调用时创建，后续工具调用编辑同一条消息；步骤数、工具名称、参数摘要、成功/失败状态随事件更新。
4. 最终回复卡：只显示正式回答，不重复状态卡已经展示的运行元数据。

状态卡和执行过程卡均使用可编辑消息；编辑失败时保留当前卡片，不发送孤立的工具行或重复状态气泡。网关停止、飞书不支持编辑或消息发送失败时，记录日志并降级到最终回复，不阻塞任务执行。

## 实时数据来源

- 模型、服务商：从当前 turn 的已解析模型/provider 读取。
- 上下文：从当前 turn 最近一次真实 token 统计读取，显示已用 token、上限和百分比；缺少统计时隐藏该行，不伪造数字。
- 阶段：由 gateway 事件驱动：received/thinking、tool.started、tool.completed、tool.failed、finalizing、completed、failed。
- 执行步骤：由真实 tool.started/tool.completed/tool.failed 事件生成，禁止从预设文本推导。

## 与现有 v0.20.0 的关系

- 复用 Feishu adapter 的 post/编辑能力和 gateway 的进度队列。
- 不安装已归档、面向 v0.15.1 的 `hermes-feishu-display-plus`。
- 不重复移植已经被 v0.20.0 吸收的媒体适配补丁。
- `runtime_footer` 不再作为最终回复的默认展示载体；实时状态卡承担运行元数据展示。

## 验收标准

- 状态卡只创建一次，至少包含真实阶段和模型；有真实 token 统计时包含真实上下文，否则不显示上下文行。
- 相同工具连续调用不会新增气泡；工具更换或状态变化只编辑执行过程卡。
- 工具失败在原步骤上标记失败并保留错误摘要，不新增第二条工具消息。
- 最终回复不含重复的模型、服务商、上下文、工作目录 footer。
- 长任务不产生周期性聊天气泡；飞书原生处理中反应仍可用。
- 飞书消息编辑失败、网关重启或单个工具异常不会导致进程崩溃或丢失最终回复。
- 单元测试覆盖状态渲染、步骤聚合、上下文缺失、失败降级和最终回复去 footer；现有 `verify.ps1` 必须继续通过。
